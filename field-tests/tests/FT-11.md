## What it checks

A reader shows what a code holds and acts only on a tap, and flags content that is not a plain link.

## Why

A code can hold anything, including a disguised link or a script-like string. The payload conventions say a reader must show the content and never act on its own; this checks that a reader does.

## Set up

1. Print the test sheet at 100% scale, or show it on a second screen.

## Steps

1. Scan each code, A to D.
2. For each, record whether the reader showed the content before doing anything, and whether anything happened (a page opened, a call started) without your tap.
3. Do not tap through on code C.

## What to record

- **Content shown before any action**, boolean, required. For each of: A link, B phone, C script, D text.
- **Something happened without a tap**, boolean, required. For each of: A link, B phone, C script, D text.

Every report also records the device, operating system, reader and its version, and the printer or screen.

## How to grade it

- **Pass:** Every code's content was shown first and nothing happened without a tap; code C offered no way to run it.
- **Partial:** Every code's content was shown first and nothing happened without a tap, but code C could be run.
- **Fail:** Anything happened without a tap.
